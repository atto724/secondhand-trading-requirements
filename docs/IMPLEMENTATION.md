# 实现与审查说明（开发文档，非实验报告）

本次以实验一 requirements.md 的 REQ-001～028、实验二四份 UML 和四张 UI 原型为依据。原图原样放在 UML 与 design_reference 中，没有用当前实现覆盖原设计。

| 014 唯一性 | schema 中部分唯一索引；同商品至多一条已确认或处理中预约 |
| 015 卖家统计 | operations；首次发布样本成交率、当前在售、区间成交分开计数 |
| 016 通知 | 本地站内消息；SAVEPOINT 隔离通知失败，业务记录仍可查询 |
| 017 审计 | 成功/失败业务操作、登录、注册、权限、日志查询导出；UI按关键词过滤，服务支持日期区间；最多返回2000条 |
| 018 性能 | benchmark.py；提供本机10万商品/100工作线程测量；不等同指定4核8GB环境验收 |
| 019 安全 | PBKDF2、随机盐、参数化SQL、角色归属校验；本地应用无网络传输，未进行TLS部署 |
| 020 可靠性 | SQLite事务、部分唯一索引、故障注入回滚测试；图片异常补偿，非断电原子事务 |
| 021 备份恢复 | SQLite备份API+图片ZIP；可恢复到全新目录；程序开启且管理员登录时每日备份，全天部署SLA未验收 |
| 022 界面兼容 | 改为Tkinter桌面版；窗口冒烟检查与部分实际窗口检查；浏览器/手机兼容不适用 |

## 架构

- database/schema：存储与增量迁移；保留旧账号和商品。
- core：权限、事务、审计、通知、金额与输入规则。
- catalog：商品生命周期、历史、图片和公开查询。
- trades：预约、取消、交付、成交、超时与电话权限。
- governance：管理员授权、违规、账号禁用、争议、更正。
- operations：消息、统计、审计导出、备份与恢复。
- editor_ui/market_ui/trades_ui/admin_ui：手写Tkinter界面。
- products/products_ui：保留早期引导阶段名称的兼容入口，业务以catalog为准。

## 本次实际验证

详细原始输出位于 verification。

- 77项自动化测试：覆盖账号、图片保存/损坏、业务状态、越权、并发与回滚、超时、备份恢复。
- GUI冒烟脚本：创建11类页面、3类窗口、切换7个主标签并退出登录，无回调异常。
- 实际桌面观察：商品卡片浏览页、管理后台审核页。其余页面仍建议学生人工逐项审查。
- Black格式检查、Pylint按pyproject配置检查；Tkinter继承深度及构造函数参数规模阈值做了明确配置。
- 构建wheel和源码tar.gz；后续改动必须重新运行build.ps1。
- 性能基准保留首次、WAL中间结果与最终结果，不隐藏未达标的早期测量。

## 仍需人工审查

学生应阅读、理解并逐行核查准备采用的代码，尤其是权限、状态转换与异常路径；自动化测试不等于穷尽所有场景。演示账号和用户提供的商品图仅用于检查，不能作为真实交易记录。

此文是程序维护说明和验证事实记录，不是实验三报告，也不代替学生独立写作。最终提交ZIP还需要学生自行完成实验报告.pdf。

## 展示层修订

统计改为指标卡、分类柱状图和中文明细表；预约快照、消息、审计、备份详情使用分区信息和记录表，图片显示缩略预览。界面时间统一显示北京时间，存储仍为UTC。新增金额、时区、角色、缺省值、密码遮蔽展示测试；空区间及嵌套详情通过窗口冒烟检查。

## 分类与演示图库更新

分类统一为数码电器、家居生活、服饰鞋包、图书文教、运动户外、兴趣娱乐、母婴用品、宠物用品、交通出行、其他闲置。旧分类优先改名保留编号，重名时迁移商品关联并停用旧分类记录；不修改预约快照。新版演示库独立存放在data/demo_gallery，15件公开商品覆盖全部10类，另外提供带图审核及草稿样例。再次启动不重复创建，也不覆盖用户审查时修改的商品。

详情页本轮采用列表页内Frame覆盖，不创建商品详情Toplevel；关闭后原列表控件、筛选和滚动状态仍保留。缩略图保留PhotoImage引用以避免被垃圾回收；图片保持比例显示，左右按钮有边界禁用。多图补充使用既有save_product和review_product服务，历史内容归档且预约快照不更新。

新增community.py与seller_ui.py实现卖家公开主页、个人资料自助编辑、卖家商品筛选和私信会话。所有资料修改仅作用于当前账号；私信查询固定为当前账号与对方，发送时事务检查双方启用状态。自动化新增公开资料敏感字段排除、私信隔离及未读/分页、禁用约束、卖家商品可见性、成交率口径和Tk导航/收发回归。

头像保存复用图片格式/大小验证及相对路径副本；数据库失败清理新副本，资料更新保留头像字段。卖家主页改为商品与私信并列，ChatPanel为输入和发送控件优先分配空间，原生映射窗口测试核对1080×740下控件未被裁出底部。Tk测试对象在主线程主动回收后再运行并发测试，避免Tcl资源在工作线程析构。

BubbleHistory使用Canvas内嵌Frame承载消息行，内外宽度同步并更新scrollregion；头像引用随控件保存；历史分页按消息ID合并去重，前插时补偿滚动位置。新增映射窗口回归验证双向气泡可见/对齐和长文本刷新去重/底部滚动。

D-017后ChatPage与SellerPage解耦：商品详情两个入口分别创建独立页；主页无ChatPanel。新回归验证点击私信按钮只创建聊天页、可发送并返回原详情，卖家主页访问不改变未读消息；最小窗口可见性测试改为独立聊天页。

ReservationsPage状态筛选采用缓存行分类和单记录动作重建：切换分类或刷新先清空旧按钮，选择行后根据reservation_actions矩阵生成操作。后台交易函数保持权威校验；预约查询补充product_status/blocked供界面提示。新增4项回归以子用例覆盖全部状态两种身份、取消发起方向、分类分割、刷新与空状态。

消息红点使用实际PhotoImage而非整行红色文本；原已读文字列移除。批量已读在单事务中按receiver_id更新两张表。最新消息回执按sender_id/receiver_id查询，不读取对方其他会话；计时器局限于打开的ChatPanel，销毁时取消。5项新增回归覆盖页内通知/红点、私信红点与批量、最新消息回执方向和新消息复位、批量作用域与幂等。

ProductRows替代三个业务列表的Treeview，提供键值选择与滚动卡片；按钮闭包先定位对应记录，再进入现有处理函数，避免跨卡片操作。主导航以无框文字按钮驱动原Notebook路由，选中页更新下划线。商品查询补充has_live供卡片展示限制；预约使用snapshot而非当前商品。新增4项回归验证导航名称/路由与1080窗口不溢出、商品卡片筛选与动作目标、活动预约隐藏编辑下架、预约快照及取消动作目标。

D-021以RESERVATION_GROUPS映射五个互斥状态集合，加全部入口。reservation_status根据当前身份生成细进度标签；reservation_actions继续使用原始细状态。新增2项回归验证交易中合并但标签/动作区分、取消争议排序和标签、无待处理记录默认全部及六入口文案。旧状态矩阵/分类覆盖测试保留。
